## Observed results

1. `/api/chat`, `/api/orders`, `/api/admin/reports` produced low p95 values in these runs (fast `401` responses).
2. `/api/products` was unreachable/timeouts (0 samples, 100% errors), causing budget failure.
3. A direct probe on 2026-05-23 confirmed `/api/products` timeout in current local runtime.

## Why PERF-201 is still blocked

1. Current local runtime is not DB-ready for `/api/products` benchmark flow.
2. The benchmark currently captures auth-failure latencies (`401`) for protected endpoints, which are not representative of seeded business-path performance.
3. Baseline-like vs hardened comparison requires stable seeded data and comparable auth context; that is not available in this local run.

## Next run requirements to close PERF-201

1. Start app against seeded, stable DB state.
2. Provide authenticated context (cookie/token) where needed for representative endpoint behavior.
3. Run benchmark twice (baseline-like and hardened) with same dataset and load profile.
4. Re-evaluate budgets and include p50/p95/error-rate interpretation in final report.

## Ready-to-run command templates

1. Baseline-like capture:

```bash
node scripts/benchmark-p95.js \
  --base=http://127.0.0.1:5000 \
  --endpoints=/api/products,/api/chat,/api/orders,/api/admin/reports \
  --requests=40 \
  --concurrency=8 \
  --timeout=5000 \
  --warmup=3 \
  --header=authorization:Bearer <token>
```

2. Hardened capture (same dataset and auth context):
